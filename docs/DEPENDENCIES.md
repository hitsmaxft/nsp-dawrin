# Dependencies and acknowledgments

Thank you to the authors and maintainers whose work makes this project possible.
The inventory below describes the source and build used by this macOS project.
Versions are the audited environment, not a promise that every newer version has
been tested. Python requirements are in `requirements.txt`; restored .NET package
versions are recorded in the translator's `obj/project.assets.json`.

## Upstream acknowledgments and local scope

The upstream project records additional tools, offline patches and community
contributions in its own [acknowledgments](https://github.com/jhaizhou-ops/d2r-mobile).
This macOS subset does not include its LFS offline gameplay patch table,
libdeflate, FLIP, iOS device tooling, or emulator-based comparison harness.
Its contributors and validation results are credited to that upstream project,
not claimed as direct contributions or validation of this project.

For a binary distribution, collect complete notices from the exact bundled
artifacts as well as the vendored source. This inventory is a source map and
acknowledgment record; the original license texts remain authoritative.

## Content format references

The package reader's PFS0/HFS0, XCI, NCA and BKTR storage layouts and counter
handling were checked against [SciresM/hactool](https://github.com/SciresM/hactool)
at `1d64a83450e025622f3468c28fc4164dad2c5ef6` (`nca.c`, `nca.h`, `bktr.h`,
`xci.h`, `hfs0.h`). The Python implementation uses its own bounded reader and
flattened range representation. The original ISC notice is retained in
[LICENSES/hactool-ISC.txt](../LICENSES/hactool-ISC.txt).

Application control fields and save allocation offsets, HIPC descriptors, CMIF
request/response layouts, and settings command IDs were checked against the libnx
authors' [source](https://github.com/switchbrew/libnx/tree/feebd026ca0f5dcc2119f46ad8e0d16ad3dd4973)
at `feebd026ca0f5dcc2119f46ad8e0d16ad3dd4973` (`nacp.h`, `sf/hipc.h`,
`sf/cmif.h`, `services/sm.c`, `services/set.c`). CPU loading mode semantics also
reference [apm.h](https://github.com/switchbrew/libnx/blob/feebd026ca0f5dcc2119f46ad8e0d16ad3dd4973/nx/include/switch/services/apm.h).
The independent host transport
in `src/macos/ipc.c` adapts these layouts to bounded local service dispatch;
libnx is not linked. Its complete ISC notice is retained in
[LICENSES/libnx-ISC.txt](../LICENSES/libnx-ISC.txt).
The controller-support result and argument header in `src/macos/input.c` also
reference `applets/hid_la.h` and `services/hid.h` at the same revision. The host
selects its existing local input device rather than launching a system applet.
The JPEG profile-image contract also references `services/acc.h` at that revision.
`src/macos/profile.m` generates an original local avatar using the system graphics
and image encoding frameworks; no profile artwork is copied or bundled.
The steady-clock time point and system-clock context layouts in
`src/host/hle_time.c` reference `services/time.h` at the same libnx revision.

## Media interface references

Software codec selection uses the public creation flags documented by the Android
Open Source Project in [OMXCodec.h](https://android.googlesource.com/platform/frameworks/base/+/569584be0e51ca6aceb53aa81b5ecac23d1ca55b/include/media/stagefright/OMXCodec.h)
(revision `569584be0e51ca6aceb53aa81b5ecac23d1ca55b`, Apache-2.0).
`src/host/hle_media.c` calls the guest's own selector; no codec implementation is
copied or bundled. Transfer-memory syscall contracts were checked against the
libnx authors' `kernel/svc.h` at the libnx revision recorded above (ISC).

The software codec registry adapter also references AOSP `include/utils/VectorImpl.h`
and `include/utils/String8.h` at revision `569584be0e51ca6aceb53aa81b5ecac23d1ca55b`
(Apache-2.0). It uses exported guest constructors and vector operations; no Android
container or decoder implementation is copied. Codec component names are required
API identifiers.

The AVC bridge uses the unmodified `H264SwDecApi.h` and `basetype.h` interface
headers from AOSP's `frameworks/av` revision
`2b6f22dc64d456471a1dc6df09d515771d1427c8`,
[`media/libstagefright/codecs/on2/h264dec/inc`](https://android.googlesource.com/platform/frameworks/av/+/2b6f22dc64d456471a1dc6df09d515771d1427c8/media/libstagefright/codecs/on2/h264dec/inc/).
They retain their Android Open Source Project copyright and Apache-2.0 notices
under `src/third_party/h264-interface/`, alongside the upstream `NOTICE`.
Only interface headers are vendored. The independent macOS decoder uses Apple's
system VideoToolbox, CoreMedia and CoreVideo frameworks, following the
[decompression session API](https://developer.apple.com/documentation/videotoolbox/vtdecompressionsession-api-collection).

### OpenMAX buffer interface

`src/third_party/openmax-interface` contains unmodified `OMX_Types.h`,
`OMX_Index.h`, and `OMX_Core.h` from AOSP frameworks/native,
[`android-7.1.2_r39`](https://android.googlesource.com/platform/frameworks/native/+/android-7.1.2_r39/include/media/openmax/).
These PacketVideo and Khronos Group headers define media buffer ownership,
flags, and timestamps. Apache-2.0 and the Khronos permission notice are retained
in the headers, with the Apache license in the adjacent `NOTICE`.
The queue adapter follows the public AOSP `SoftAVC` lifecycle and `List` ABI;
its queue scheduling and native decoder integration are local implementations.
